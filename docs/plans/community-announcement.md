# План анонса aoe2-lsp в профильных сообществах

Статус: план. Запускать после публикации v1.0.0: зелёный тег, расширение
на Marketplace/Open VSX (#47). Пакетные менеджеры (winget/brew, #49)
отложены до запроса пользователей — в постах их не обещать.
Промежуточный «мягкий» анонс в узких чатах картоделов возможен
раньше — по решению владельца проекта.

Продукт одной строкой: LSP-сервер для RMS и XS — диагностика,
автодополнение, hover-доки по командам и атрибутам, навигация,
форматирование, прямо в редакторе.

## Две категории постов

### Категория A — сообщества об Age of Empires (RU + EN)

Широкая аудитория: игроки и авторы контента, LSP-жаргон не использовать.
Акцент: «писать карты стало проще» — ошибки видны до запуска игры,
доки по командам по ходу набора, форматирование одним нажатием.

- Формат: короткий пост (3–6 предложений) + GIF 10–20 сек (hover,
  автодополнение, диагностика на реальной карте) + одна ссылка на README.
- EN-площадки:
  - официальный Discord AoE2:DE — канал моддинга/scenario design
    (спросить разрешение модераторов канала);
  - r/aoe2 — пост с GIF, проверить правила про self-promotion;
  - AoEZone (aoe2.de) — тема в разделе scenario design/modding.
- RU-площадки (конкретные чаты уточнить на момент запуска):
  - Telegram-чаты AoE2 RU-сообщества (общие и по моддингу);
  - VK-паблики по AoE2;
  - RU Discord-серверы AoE2.

### Категория B — профильные сообщества картоделов (RMS/XS)

Аудитория: авторы RMS-скриптов и XS-библиотек. Технический тон, полный
набор фич, честный список ограничений, прямой призыв к фидбеку через
GitHub issues. Это главная аудитория: они дают ранний фидбек и багрепорты.

- Формат: пост средней длины — что умеет сервер (перечень фич), какие
  редакторы (VS Code-расширение из Marketplace, Neovim через lspconfig;
  Notepad++ — через NppLspClient, плагин экспериментальный, поддержка не
  выверена), как поставить (3 команды / ссылка на Editor setup), куда
  сообщать о проблемах.
- Площадки:
  - каналы RMS/XS в моддинг-дискордах AoE2 (официальный сервер и
    крупнейший моддинг-сервер; актуальные инвайты/каналы уточнить);
  - XS-сообщество (дискорд картоделов XS — инвайт уточнить);
  - AoEZone — узкотехническая тема в разделе RMS/scenario scripting;
  - Steam Community — гайд по установке (долгоживущий формат, обновлять
    по мере релизов);
  - RU-чаты картоделов (уточнить у знакомых авторов карт).

Порядок внутри категории B: сначала узкие чаты (собрать фидбек),
затем AoEZone/Steam.

## Активы (готовятся один раз, до первого поста)

- 4 текста постов: A-EN, A-RU, B-EN, B-RU (RU-версии — адаптация, не
  подстрочный перевод).
- GIF: hover-доки по команде/атрибуту, автодополнение, диагностика
  (ошибка + quick fix), форматирование. Снимать на актуальном релизе.
- Скриншоты-стопкадры для площадок без GIF (VK, форумы).
- Ссылки: README (install + editor setup), GitHub Releases, Marketplace
  (после #47), issue-трекер для фидбека.

## Порядок запуска

1. Дождаться зелёного v1.0.0 и публикации расширения.
2. Подготовить активы; тексты постов показать владельцу проекта на
   контроль тона и фактов.
3. Категория B: узкие чаты → фидбек → фиксы → AoEZone/Steam.
4. Категория A: RU-чаты и EN-площадки после первого цикла фидбека из B.
5. Инфраструктурные апдейты (новые версии; winget/brew — только если
   появятся по запросу пользователей) — короткими дополнениями в те же
   темы, не новыми постами.

## Этикет и риски

- В каждом чате — сначала спросить модераторов; один пост на сообщество,
  апдейты в ту же тему.
- Не обещать непроверенное: Notepad++-секция помечена в README как
  не выверенная; в постах B это отражать.
- В постах указывать лицензию/атрибуцию (KB унаследована от GPL UGC
  Guide — раскрыто в README); вопросы авторства AoE-контента закрывать
  ссылкой на дисклеймер README.
- Feedback-петля: мониторить issues после каждого поста, критичные
  багрепорты чинить до постов следующей площадки.
