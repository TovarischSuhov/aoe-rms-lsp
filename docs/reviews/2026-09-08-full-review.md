## 🔴 Критичная

### 1. Паника парсера RMS на файле без финального `\n` — `rms/parse.go:525`

`endXsBlock` (вызывается из `closeAll:158`) вычисляет `p.pos(end, 0)`,
который читает `p.starts[end]`. Если XS-блок не закрыт и файл не
заканчивается переводом строки, цикл обрезки пустых строк не
срабатывает и `end == len(p.lines)` → index out of range.

- Репро: `rms.Parse("#includeXS\nvoid main() { int x = 1; }", "t.rms")`
  → `panic: index out of range [2] with length 2`. Паникует и просто
  `"#includeXS"` без `\n`.
- Проду: `didOpen`/`didChange` любого .rms с inline-XS, сохранённого
  без финального перевода строки (частый случай), — паника в горутине
  jsonrpc-хендлера, падение всего сервера.
- Нарушение контракта CODEMANIFEST rms (Constraints: не паниковать).
- Фикс: в `endXsBlock` обрабатывать `end == len(p.lines)` (конечная
  позиция = конец последней строки), не индексируя `starts`.
- Уверенность: высокая, подтверждено репро.

## 🟡 Существенные

### 2. Ложные `undefined symbol` на каждом for-цикле — `xs/parse.go:526`, `analysis/analyzer.go:250`

`parseFor` раскладывает init-декларацию `for (int i = 0; …)` в
`StmtFor.Exprs`, а сбор локалей (`analysis` `collectLocals`, xs
`collectLocals`/`appendLocals`) смотрит только на узлы `StmtDecl`.
Переменная цикла нигде не видима.

- Репро: `AnalyzeXs` на `void main() { for (int i = 0; i < 10; i++) { int j = i + 1; } }`
  → 4 × `undefined symbol "i"` (init, cond, step, body).
- Также: `Definition("i")` → found=false; `VisibleAt` не содержит `i`
  → completion не предлагает переменную цикла.
- Самый массовый паттерн цикла в XS даёт ложные error-диагностики.
- Уверенность: высокая, подтверждено репро.

### 3. Сдвиг номеров строк после `\` + `\n` в строковом литерале — `xs/parse.go:1441`

`scanString` на escape-последовательности делает `s.pos += 2` и
пропускает `\n` без `s.line++`/`lineStart`. Все позиции (диагностики,
hover, definition, completion) после такой строки сдвинуты на одну
строку вверх.

- Репро: `string s = "abc\` + `\n` + `DEF";\nint z = 1;` — декларация
  `z` на физической строке 3 (0-based line 2) получает `Line=1`.
- Уверенность: высокая, подтверждено репро.

### 4. Top-level мультидекларации не парсятся — `xs/parse.go:103`

`parseTypedDecl` не обрабатывает запятые: `int a = 1, b = 2;`
(валидный XS) → две ошибки («expected ;», «unexpected "," at top
level»), декларация `b` теряется из completion/навигации. Внутри
функций `parseLocalDecl` запятые обрабатывает — асимметрия.
Уверенность: высокая.

### 5. Мёртвый warning о незакрытом блоке — `rms/parse.go:398`

В `closeScopes` условие `i < len(p.scopes)-1` всегда false: `len`
уже усечён предыдущей итерацией (`p.scopes = p.scopes[:i]`, строка
404) до `i+1`. Сравнивать нужно с исходной длиной среза.

- Репро: `start_random / if 1 / percent_chance 50 / create_terrain
  GRASS / end_random` — `end_random` молча закрывает незакрытый `if`,
  0 диагностик вместо предупреждения.
- Уверенность: высокая.

### 6. Некорректные позиции для не-ASCII при клиенте без utf-8 — `server/server.go:98`

Сервер соглашается на utf-8 только если клиент его предложил; иначе
молча остаётся на дефолтном utf-16, но `toProtocolPos`/
`fromProtocolPos` проксируют байтовые колонки парсеров без
конвертации.

- Сценарий: `/* Поколение */ create_land …` — колонки правее
  кириллицы во всех diagnostic/hover/completion диапазонах сдвинуты
  (BMP-символ: 2 байта = 1 UTF-16 юнит).
- Для русскоязычных комментариев (вероятная аудитория) — постоянный
  сдвиг.
- Уверенность: высокая (механизм), средняя (насколько осознанный
  trade-off).

## ℹ️ Мелкие

### 7. Пустой фантомный XsBlock от `#includeXS file.xs` — `rms/parse.go:468`

Каждая директива с файловым аргументом включает inline-режим, а
следующая директива/секция мгновенно терминирует блок: `Code=""`,
`Range` нулевой ширины — мусорный узел в documentSymbol. Стоит не
добавлять блок, если `end == xsStart`. Уверенность: средняя.

### 8. Кэш диска хранит URI первого запросившего — `include/resolver.go:171`

`loadDisk` кэширует `parseFile(uriArg, …)` по каноническому пути;
`definitionInRms` возвращает `Target{URI: f.uri}`. При двух
написаниях URI одного файла (symlink, регистр на macOS) Definition
вернёт «чужое» написание — редактор может открыть второй буфер. Плюс
TOCTOU-окно: fingerprint берётся до чтения файла. Уверенность:
средняя, эффект узкий.

### 9. Include-пути не ограничены рабочей областью — `include/resolver.go:118`

`#include "../../../../etc/passwd"` резолвится и читается. Каталог
как цель include проходит `os.Stat`, но проваливается в `ReadFile` →
попадает в `Resolved`, но не в `Missing` (молчаливая потеря без
диагностики). Локальный инструмент — серьёзность низкая. Уверенность:
высокая.

### 10. Closure каждого includer вычисляется дважды в References — `include/resolver.go:321`

`closureContains` + повторно для сбора; каждый вызов перепарсивает все
editor-state документы замыкания. На каждый keystroke × число открытых
документов. Только производительность. Уверенность: высокая.

### 11. `//` и `/*` внутри строковых литералов гасятся как комментарии — `rms/parse.go:715`

`blankComments` не учитывает кавычки: в `#include "a//b.rms"` символы
`//` внутри кавычек заменяются пробелами → Range пути растягивается до
конца строки, Path искажается. Редкий, но реальный вход. Уверенность:
высокая.

## Категории без находок

- **Гонки/мутации shared state в server** — DocStore и кэш Resolver
  под мьютексами, AST после парса иммутабельны и только читаются,
  `exit` через `sync.Once`.
- **Утечки горутин / бесконечные циклы** — все циклы восстановления
  (`parseBlock`, `parseCase`, `parseArgs`, `syncStmt`, лексер «never
  zero-width») имеют гарантию прогресса.
- **Include-циклы/глубина** — visited-сет по каноническому пути,
  `maxDepth=64`, `maxFiles=1024`, `#include` A→B→A обрабатывается.
- **Диагностики (severity/kind-маппинг)** — корректен; проблемы только
  в №2 (ложные срабатывания) и №5 (недостижимый warning).

## Репро (№1–№3)

Минимальная программа (проверена 2026-09-08, модуль aoe2-lsp через
`go mod edit -replace`):

```go
// №1: паника
_, _ = rms.Parse("#includeXS\nvoid main() { int x = 1; }", "t.rms")
// → panic: runtime error: index out of range [2] with length 2

// №2: ложные undefined
xf, _ := xs.XsParse("void main() { for (int i = 0; i < 10; i++) { int j = i + 1; } }", "t.xs")
// analysis.Analyzer.AnalyzeXs(xf, nil) → 4 × `undefined symbol "i"`

// №3: сдвиг строк
xf3, _ := xs.XsParse("string s = \"abc\\\nDEF\";\nint z = 1;", "t3.xs")
// Decl "z": Range.Start.Line == 1, физически строка 2 (0-based)
```
