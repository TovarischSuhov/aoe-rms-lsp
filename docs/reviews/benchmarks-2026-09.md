# Бенчмарки ячеек — 2026-09

Первый базовый срез производительности горячих путей (до этого бенчмарков
в репозитории не было). Замеры на состоянии слияния PR operational-readiness
(debug + corpus-фиксы парсера + бенчмарки), Go 1.26, linux/amd64 (8 ядер),
под cgroup-песочницей MemoryMax=1500M, `-benchtime 300x` (фиксированное
число итераций).

Входы — детерминированные генераторы в каждом `*_bench_test.go`
(size-классы small/medium/large, форма реальных карт: секции, скобочные и
бессобачные attribute-блоки, условия, комментарии). Перезапуск:

```sh
go test ./internal/... -bench . -benchmem -run XXX -benchtime 300x
```

## Слабые места и действия

### 1. Сканер xs — 64% всех аллокаций (исправлено)

pprof (`-memprofile`): `xscanner` конвертировал каждый токен
`string([]byte-срез)` и копировал вход в `[]byte` — на 64% аллокаций
XsParse. Фикс: сканер работает по `string`-источнику, тексты токенов —
подстроки с общим backing array (zero-copy).

A/B (benchstat, `-benchtime 200x -count 5`):

| Метрика | До | После | Δ |
|---|---|---|---|
| allocs/op (geomean) | 23.3K | 14.6K | **−37.4%** (p<0.01) |
| sec/op (geomean) | 8.79ms | 8.50ms | −3.3% (не значимо, n=5) |
| B/op (geomean) | 10.1Mi | 10.0Mi | −1.3% |

Меньше heap-объектов → меньше GC-давления; время в пределах шума.

### 2. Пересборка документа на каждый запрос (архитектура, осознанно)

Хендлеры stateless: hover/completion/signatureHelp/documentSymbol делают
полный `Parse`/`XsParse` документа. Реальная карта корпуса ~90KB ≈ 4ms
на запрос; мегакарта 400KB+ ≈ 17–25ms. Для LSP-интерактивности приемлемо
(корпус: 100 карт × полный цикл запросов = 3.3с). Лever ускорения —
кэш распарсенных версий по (текст, версия) — требует изменений в
контракте server/DocStore, вынесен в follow-up плана задачи, не сделан.

### 3. `kb.NewStore` — 5.8ms на старте

Одноразовая стоимость при запуске сервера (embedded JSON → индексы).
Действий не требует; отмечено как точка отсчёта.

### 4. Скан без слабых мест

`hints` (1.9µs), `complete` (0.9–2.1µs), `analysis` (112–232µs),
`SymbolAt` (33µs, 0 аллокаций) — микросекундные, действий не требуют.
`Closure` тёплый 44–145µs, масштабируется с глубиной цепочки, stat-кэш
диска работает (первое вычисление дороже, далее light-copy по fingerprint).

## Регресс-контроль

Бенчмарки детерминированы (генераторы без рандома), работают под
memory-cap, попадают в `go test -bench`; сравнение через `benchstat`
(см. A/B выше) — правило из CLAUDE.md.
