# rms: `#`-слово в позиции атрибута — диагностика + refusal (#95)

## Current State

- `internal/rms` — классификация строк в `run` (parse.go:82): строка с
  ведущим `#`, не являющаяся директивой, безусловно записывается как
  hash-комментарий (parse.go:136-141, `recordExcluded` +
  `recordHashComment`) — в том числе внутри открытого `{ }`-блока
  атрибутов
- лексер принимает `#` как начало и продолжение слова (parse.go:1160):
  однострочный блок `create_land { #weird 1 }` парсится через
  `commandLine` → `splitArgsBlock` → `inlineAttributes` (parse.go:350),
  и `startsAttribute` (parse.go:379) пропускает `#weird` как имя
  атрибута — без диагностики
- форматтер перепечатывает однострочный блок канонически многострочно;
  при reparse ведущий `#weird` уже комментарий — атрибут и блок
  теряются: `format(format(x))` расходится на первом проходе,
  `parse(format(x))` теряет атрибут (сценарий issue #95)
- контракт комментариев (`.usages/rms-parsing.md`, «Comment extents»):
  `#`-строки (не директивы) — комментарии везде, включая блоки.
  Reparse-сторона корректна по контракту; некорректна молчаливая приёмка
  `#`-слова в атрибутной позиции
- `internal/format` — `refuse` (rms.go:66) уже превращает первую
  error-диагностику в `ErrParseErrors` → `RMS()` отказывает;
  инвариантный тест трактует отказ как skip («Refused inputs promise
  nothing», invariants_test.go:14)

## Description

Направление (b) из issue, утверждено пользователем: парсер диагностирует
error-степенью слово с ведущим `#` в позиции имени атрибута
(инлайн-путь `inlineAttributes`); форматтер отказывает по существующему
механизму refusal — код форматтера не меняется. Патологический
инлайн-вход перестаёт молча деградировать: пользователь видит ошибку,
форматирование файла отказывает целиком. Код-якорь целевого поведения:

```go
// create_land { #weird 1 }  →  диагностика на токене #weird:
p.reportf(toks[i].at, common.SeverityError, "syntax",
	"%q is not an attribute name: #-lines are comments", toks[i].text)

// форматтер отказывает по существующему refuse, без правок format:
_, err := format.RMS("create_land { #weird 1 }", format.Options{})
// err errors.Is → format.ErrParseErrors
```

Формулировка сообщения — английская, по образцу существующих
(`unexpected %q`); точный текст выбирается при реализации и пинится
тестом. Recovery-форма (пропуск токена по образцу unexpected-ветки либо
атрибут с диагностикой) — решение реализации: форматтер отказывает по
диагностике в обоих случаях, наблюдаемое поведение пинуют тесты.

## Scope

**In scope:**

- `internal/rms`: error-диагностика (code `syntax`) на `#`-слове в
  позиции имени атрибута в `inlineAttributes`
- тесты internal/rms (table-driven): диагностика — позиция/severity/
  code; `#`-комментарий внутри блока остаётся комментарием без
  диагностики; `#`-слово в позиции значения — без новой диагностики
  (граница)
- `internal/format`: тест отказа — `RMS` на инлайн-`#`-входе возвращает
  `ErrParseErrors` (код форматтера не меняется)
- корпус-гейт: байт-идентичность master
- при необходимости — уточняющая строка в `.usages/rms-parsing.md`
  (раздел Comment extents) тем же PR

**Out of scope:**

- `#`-слова в позициях значений/аргументов (симметричны раунд-трипу,
  инвариант не ломают)
- модель `#`-комментариев и контракт `RmsFile.Comments` (reparse-сторона
  корректна по контракту)
- mid-line комментарии (лексическая тема глубже задачи)
- соседние слоты: #96 (zero-width Expr), #94 (interleaving), #135
  (mergeComments при EOF)

## Acceptance Criteria

- `create_land { #weird 1 }` → ровно одна error-диагностика `syntax` на
  токене `#weird`; атрибут не принимается молча (без диагностики)
- строка с ведущим `#` внутри блока (`# plain comment`) остаётся
  комментарием в `RmsFile.Comments`, без диагностики — контракт не
  меняется
- `format.RMS` на инлайн-`#`-входе → `ErrParseErrors` (refusal), код
  форматтера не тронут
- инвариантные тесты: класс покидает поверхность сходимости через
  refusal (skip), не через divergence
- корпус-гейт байт-идентичен master; `make check` и `goga contract`
  затронутых ячеек зелёные

## Risks and Constraints

- диагностика не должна задеть легитимные инлайн-блоки корпуса: все
  имена атрибутов в kb без `#`; страховка — корпус-гейт
- `startsAttribute` размечает и границы значений (цикл `j` в
  `inlineAttributes`) — проверка `#` не должна сдвинуть разбиение
  обычных блоков
- готчи проекта: lint-хук блочит коммиты молча; `.claude/`-симлинки не
  коммитить; тесты — только под memory cap
