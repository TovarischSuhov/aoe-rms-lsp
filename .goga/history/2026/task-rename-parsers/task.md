# rename-парсеры: rename-сайты с затенением в xs/rms

## Current State

- `xs`: `Definition(pos)` уже резолвит биндинг с затенением (innermost
  объемлющая декларация; параметр/локаль затеняют топ-левел). Но
  `ReferencesAt`/`References` — синтаксические, по имени: одноимённые
  символы разных областей видимости не различаются (зафиксировано в
  контракте xs). Rename по ним переименовал бы и чужое затенение
- `rms`: `ReferencesAt`/`References` — по слову-токену («локальных
  деклараций в RMS нет»); в матчи попадает словарь языка (имена секций,
  команд, атрибутов) и ident/const-значения. При этом `#const`/`#define`
  — реальные пользовательские декларации, для rename их надо отличать
  от языка
- rename-поверхности в парсерах нет; серверные хендлеры
  `PrepareRename`/`Rename` — подзадача #44 (include+server)

## Description

Парсеры отдают переименовываемые сайты с корректным затенением:

- **xs**: по позиции резолвится конкретный биндинг (тот же алгоритм,
  что `Definition`) и возвращаются все вхождения **только этого
  биндинга** — name-range декларации + её ссылки; одноимённые символы
  других скоупов исключаются. Builtin/неизвестное/не-идентификатор —
  `found=false` (позиция не переименовываема)
- **rms**: переименовываемые сущности — имена `#const`/`#define`
  (декларация + использования как ident-значения); словарь языка
  (команды/атрибуты/секции) — не переименовываем; inline-XS блоки
  делегируются xs-части (XsBlock несёт координаты)
- per-file API; кросс-файловая склейка по include-замыканию — #44

## Scope

**In scope:**
- xs: скоуп-aware резолвинг сайтов переименования (затенение:
  параметр/локаль vs топ-левел, вложенные блоки)
- rms: аудит и фиксация переименовываемых сущностей (`#const`/`#define`),
  per-file сайты декларации + использований
- делегация inline-XS: сайты в координатах .rms
- тесты: затенение (одноимённые в разных скоупах не смешиваются),
  builtin/keyword → found=false, rms: декларация+использования,
  имя команды не предлагается
- контракты ячеек (CODEMANIFEST) обновить

**Out of scope:**
- серверные `PrepareRename`/`Rename`/`WorkspaceEdit` и склейка по
  include-замыканию (#44: include+server)
- изменения существующих references/diagnostics/semantic tokens
- клиент VS Code; format (подзадачи 5–6 эпика)

## Acceptance Criteria

- сайт на локальной переменной возвращает только её вхождения;
  одноимённая из другого скоупа не попадает в результат
- позиция на builtin/ключевом слове/команде/атрибуте/секции —
  found=false (не переименовываемо)
- rms: `#const`/`#define` — декларация + все использования;
  имя команды не предлагается к переименованию
- inline-XS в .rms — сайты считаются по xs-правилам в координатах .rms
- `make check` зелёный; `goga lint`/`goga contract` по затронутым
  ячейкам зелёные

## Risks and Constraints

- семантика затенения должна совпасть с `Definition` — расхождение даст
  rename≠definition; покрыть тестами на тех же фикстурах
- если аудит найдёт переименовываемые rms-сущности вне
  `#const`/`#define` — решение design-этапа, не молчаливое расширение
  скоупа
- производительность: резолвинг — разовые вызовы на запрос, индексы
  вхождений уже существуют

## Existing Architecture

- `internal/xs` — `XsFile` (`SymbolAt`/`Definition`/`ReferencesAt`/
  `References`/`Symbols`/`VisibleAt`), `Decl`/`Param`/`Stmt`/`Expr`
- `internal/rms` — `RmsFile` (`StatementAt`/`ReferencesAt`/`ArgAt`/
  `EnclosingRanges`), `XsBlock` (координаты inline-XS; semantic tokens
  уже делают сдвиг в координаты файла — прецедент)
- сервер: definition/references по замыканию — потребитель будущих
  сайтов (#44)
