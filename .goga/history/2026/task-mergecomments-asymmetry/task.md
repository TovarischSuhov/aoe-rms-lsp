# mergeComments-асимметрия: `#tail /* oops` при EOF без перевода — сходимость со 2-го прохода

Зеркало — GitHub issue #135 (открыта, метки bug/P3/size:S-M), PR закрывает
`Fixes #135`. Найдено финальным гейтом задачи #126 (task/format-unclosed-block).

## Current State

Незакрытый `/*`, открытый на плоской `#`-строке, когда EOF приходится ровно
на конец строки и завершающего перевода строки нет (последняя строка файла
вида `#tail /* oops`), на первом разборе проглатывается `#`-экстентом целиком
(`insideRange`: End сканированного комментария == End `#`-экстента == EOF).
Форматтер добавляет хвостовой EOL (`result()`), и на reparse незакрытый `/*`
выходит за пределы `#`-строки — `commentCut` расщепляет её на `#…` + `/* …`:

- `format(x) ≠ format(format(x))` на один байт (первый проход печатает одним
  комментарием, второй — расщепленным)
- со второго прохода байт-идентично, закрыватели постоянны по проходам
- error-диагностик нет — вход не refusal

Класс подтверждён на 12 вариантах свипа финальным ревью #126 (PR #137 закрывает
рост синтеза закрывателей и сжимает этот класс с нестабильного на master до
ограниченного; корень остаётся). Инвариант «Сходимость форматтера» в
`knowledge/architecture/stability-invariants.md` называет класс 2 (единственный
оставшийся эскейп RMS).

## Description

Асимметрия границ: на первом проходе граница `#`-экстента (EOF) совпадает с
концом скана комментария, и `insideRange` считает его внутренним; после
добавления EOL форматтером граница сдвигает на байт, тот же байт уже снаружи —
расщепление. Корень — в `internal/rms`, кандидат на фикс: границы
`commentCut`/`insideRange` (`mergeComments`, parse.go:1023-1097) либо
нормализация EOL до скана.
