## Description

Печать XS в каноническом стиле и расширение formatting-хендлера на
.xs-документы.

1. `format.XS(source, opts)` — принтер XS из AST: отступы по `Options`,
   раскладка деклараций/стейтментов/выражений, якорение комментариев по
   образцу RMS-принтера, EOL входа сохраняется.
2. Стратегия потерь AST — **гибридная** (решение пользователя
   2026-10-12): каноническая печать там, где AST полон; дословные срезы
   исходника для конструкций из аудита, которые AST не воспроизводит
   (аналог структурных команд RMS-принтера). Правки парсера/AST не
   входят; находки аудита остаются фиксацией, отдельные задачи —
   опционально после.
3. Хендлер сервера: .xs-документы идут в `format.XS`; отказ и маппинг
   опций — по образцу RMS-ветки.

Целевой вызов (имена — по образцу `format.RMS`):

```go
out, err := format.XS(src, format.Options{TabSize: 4})
// err — sentinel при error-диагностиках XsParse (классификация
// errors.Is); out пуст при отказе. Конструкции с потерями AST
// печатаются дословными срезами источника, не синтезом.
```

## Scope

**In scope:**

- `internal/format`: точка входа `XS` рядом с `RMS`, общие `Options`;
  `CODEMANIFEST` — Imports xs (`XsParse`, `XsFile`, usages
  `xs-parsing`) и контракт `XS` (goga-change flow, не read-only правка)
- гибридная печать: канонический принтер + дословные срезы для находок
  аудита; правило — конструкция с дословным срезом печатается срезом,
  её комментарии заякорены как обычно

  правила с модификаторами, event, switch/case, condition/action,

  (сравнение без Range); `XS(XS(x))` байт-идентичен; полнота
  комментариев; на golden и на .xs корпуса (пропуск, если `.corpus` не

## Acceptance Criteria

- `format.XS`: `parse(XS(x))` структурно эквивалентен `parse(x)` на
  golden и корпусе .xs; `XS(XS(x))` байт-идентичен `XS(x)`; все тексты
  комментариев входа присутствуют в выходе байт-в-байт; EOL входа

## Risks and Constraints

- Гибрид опирается на `Range`-экстенты узлов; у `Decl.Range` хвосты без
  закрывающих `}` (аудит) — границы срезов брать по проверенным
  правилам; дыры ловит инвариант байт-сохранности (прецедент RMS:
  команда со структурным первым словом → сырые байты среза)
- Незакрытые конструкции при error-диагностиках — отказ до печати
  (прецедент RMS: error → refusal)
- Комментарии внутри срезаемых регионов (тело голого блока) собираются
  лексером независимо от разбора — накрыть тестом, что они заякорены и
  не дублируются
- Язык документа для диспетчеризации сервер знает до разбора
  (languageId/расширение) — .xs не должен пробиваться через RMS-принтер
- fuzz: xs-фаззер существует; форматный фаззер (вход → `XS` → `XS`,
  идемпотентность) — по образцу format-фаззера волны #96, seed из
  фикстур
- knownDivergent-механику RMS (3-й проход) в XS вслепую не переносить:
  расхождения фиксировать находками, не маскировать
- Тесты — только под memory cap (cgroup-песочница, CLAUDE.md)
