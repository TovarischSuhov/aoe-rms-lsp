# fix-stdio-flag: толерантность к неизвестным флагам CLI (#37)

## Current State

`cmd/aoe2-lsp/main.go` определяет единственный флаг `-debug`; README
фиксирует «No other flags». Issue #37: пользователь Windows запускает
релизный бинарник через клиент, который по конвенции добавляет `--stdio`
(Neovim-style конфиги, generic LSP-обёртки VS Code) → Go `flag` отвечает
`flag provided but not defined: -stdio`, exit code 2, соединение не
поднимается. Собственное расширение `editors/vscode` передаёт `args: []`
и не затронуто — ломается совместимость с внешними клиентами. Любое
расхождение флагов клиента и сервера сегодня фатально, хотя для stdio-транспорта
оно безразлично.

## Description

Неизвестные флаги логируются warning'ом в stderr, игнорируются — сервер
продолжает работать. Специальной регистрации `-stdio` нет: своё расширение
флаг не передаёт, предупреждение для внешних клиентов честное («пусть
шумит — мы его не ожидаем»). Позиционные аргументы и всё после `--`
проходят как есть; ошибки значений известных флагов (например
`-debug=x`) логируются error'ом и оставляют дефолты — старт никогда не
прерывается из-за аргументов командной строки.

## Scope

**In scope:**
- `cmd/aoe2-lsp/main.go`:
  - `flag.NewFlagSet(..., flag.ContinueOnError)` с выводом пакета в
    `io.Discard` — свои сообщения идут через логгер
  - `splitUnknownArgs(fs, args) -> (known, unknown)`: разбиение
    аргументов на распознаваемые флагset'ом (включая `-name=value`) и
    неизвестные flag-подобные; `--` — терминатор, позиционные — как есть;
    все флаги булевы, known-аргумент не поглощает следующий
  - warnings `ignoring unknown flag` после инициализации логгера
    (stderr; stdout остаётся только для протокола)
  - ошибка парсинга (`-debug=x`) — error-лог и продолжение на дефолтах
- `cmd/aoe2-lsp/main_test.go`: table-driven тест `splitUnknownArgs`
- README, секция Install & run: unknown flags логируются и игнорируются,
  старт не прерывается
- Ссылка на issue в коммите (`Fixes #37`) — закроется при попадании в
  master

**Out of scope:**
- спец-регистрация `-stdio` (отклонена: пусть предупреждает как все
  неизвестные — своё расширение флаг не передаёт)
- семантика `--version` (остаётся спец-кейсом `os.Args[1]`, без
  `flag.Parse`)
- extension и серверная логика (`internal/*`) — не затрагиваются

## Acceptance Criteria

- `aoe2-lsp -stdio`, `aoe2-lsp --stdio`, `aoe2-lsp -bogus --transport=pipe`
  стартуют: warning `ignoring unknown flag` в stderr, сервер жив (до
  фикса — exit 2)
- `-debug` и поведение без флагов не изменились; `-debug=x` — error-лог,
  старт на дефолтах
- `--version` работает как раньше
- тест `splitUnknownArgs` зелёный (both-ветки: known/unknown)
- README отражает поведение
- `make check` зелёный; ячейки не затронуты — `goga contract` не требуется

## Risks and Constraints

- Фильтрация flag-подобных аргументов до парсинга — единственная
  нетривиальная логика; ограничение зафиксировано в контракте функции:
  все зарегистрированные флаги булевы (known-аргумент не поглощает
  следующий); появление нефлагового флага потребует доработки
  `splitUnknownArgs`
- Логирование неизвестных флагов уровня Warn: шум для осознанно
  передающих `--stdio` клиентов приемлем (наш клиент не передаёт)
- stdout остаётся чистым для протокола — все сообщения только в stderr
