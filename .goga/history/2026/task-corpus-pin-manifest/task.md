# corpus-pin-manifest: сверка локального .corpus с пином corpus-sources.txt

Зеркало — GitHub issue #127 (уже открыта, новая не создаётся), PR закрывает
`Fixes #127`.

## Current State

`scripts/corpus-fetch.sh` при вызове всегда качает и сэмплирует по пину;
пропуск fetch-а «на диске уже есть сэмпл» живут в вызывающих сторонах —
Makefile-таргет `corpus` (`find .corpus -type f | wc -l >= 100`) и ручной
skip-шаг corpus-джобы CI. Нигде содержимое `.corpus` не сверяется с
`scripts/corpus-sources.txt`. CI кэширует `.corpus` по
`hashFiles('scripts/corpus-sources.txt')` и потому всегда синхронен; дыра —
локальные машины: устаревший сэмпл живёт вечно (наблюдение 2026-09-22,
#127: сэмпл, скачанный до перепина 12377bc, дал ложные падения корпусных
тестов `internal/format` и заблокировал docs-only коммит; свежий fetch —
всё зелёное).

## Description

Манифест пина внутри сэмпла + сверка на каждом пути использования:
несовпадение → перекачать (там, где сеть доступна) либо громкая ошибка с
подсказкой (не молчаливый пропуск).

## Scope

**In scope:**

- `corpus-fetch.sh`: после успешного сэмплирования записывать
  `<dest>/.sources-hash` — sha256 по `corpus-sources.txt` + `CORPUS_COUNT`
  (размер влияет на выборку; формат строки — на усмотрение реализации,
  например `<sha>:<count>`); режим/функция проверки «сэмпл на диске
  соответствует пину?» для переиспользования вызывающими сторонами
- Makefile `corpus`: условие пропуска fetch-а теперь требует и счётчик,
  и совпадение манифеста; рассинхрон → перекачать `corpus-fetch.sh`
  перед гейтом (с сообщением о перепине)
- CI (`ci.yml`, corpus-джоба): ручной skip-шаг проверяет манифест тоже
  (cache hit его обычно гарантирует — пояссная защита); fuzz-джоба
  осознанно без изменений (деградация до фикстур при промахе кэша —
  проектное поведение)
- скрытый файл в `.corpus` не попадает в globs тестов (`*.rms`) и не
  ломает счётчик (≥ 100)
- Дока: строка в README (Development, про `make corpus` и перепин) +
  `knowledge/runbooks/verification.md` — заменить предупреждение из #127
  на описание сверки (тем же PR, по правилам базы знаний)

**Out of scope:**

- смена пула/пина (`--update` остаётся ручным)
- обучение скип-логики самих корпусных тестов манифесту — точки входа
  (make/CI) закрывают проблему, тесты продолжают скипаться по отсутствию
- счётчик ≥ 100 как sanity-floor сохраняется

## Acceptance Criteria

- чистый клон + `make corpus`: манифест записан; повторный `make corpus`
  пропускает fetch, сеть не нужна
- имитация перепина (правка байта в `corpus-sources.txt`): `make corpus`
  перекачивает; в оффлайне — громкая ошибка с подсказкой, не молчание
- сценарий #127 воспроизводится и разрешается: устаревший `.corpus` →
  `make corpus` перекачал → `go test ./internal/format/` зелёный
- `bash -n scripts/corpus-fetch.sh`, `make check`, `goga lint` — зелёные;
  CODEMANIFEST ячеек не затронуты (скрипты/Makefile/CI/дока)

## Existing Architecture

- `scripts/corpus-fetch.sh` — fetch + детерминированное сэмплирование,
  `--update` — перепин до голов репозиторев пула
- `Makefile` (таргет `corpus`), `.github/workflows/ci.yml` (джобы
  `corpus`, `fuzz` с кэшем по хэшу пина)
- корпусные тесты `internal/format` (`invariants_test.go`, `rms_test.go`)
  скипаются без `.corpus`; гейт `cmd/corpus` — чёрный ящик по LSP-циклу
