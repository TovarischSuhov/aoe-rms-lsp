# ZR@-распаковка: zip-архивы в корпусе вместо пропуска

## Current State

- `scripts/corpus-fetch.sh` при загрузке детерминированного сэмпла
  отсеивает ZIP-payload по PK magic (7 архивов попало в сэмпл 100 до
  отсева) — архивы формата ZR@ (aoe2map.net «Zip Random») не попадают в
  корпус, хотя содержат реальные текстовые скрипты.
- Пул: 16 ZR@-архивов (из 236 записей), исследование показало: **в каждом
  ровно один .rms-скрипт** (иногда рядом мусорные файлы — фото/readme;
  `ZR@Shallow trap` содержит 8 файлов, из них 1 скрипт). Внутренние имена
  отличаются от имён архивов (`ZR@HonysRumbleV7.rms` → `T90V7.rms`).
  Оценка follow-up «~30–40 карт» — завышена: фактически +16.
- `internal/corpus` (Runner/cmd) работает с директорией файлов — изменений
  не требует: достаточно, чтобы fetch распаковывал архивы на этапе
  загрузки.

## Description

Распаковывать ZR@-архивы в `scripts/corpus-fetch.sh` вместо пропуска:
извлекать `.rms`/`.xs` из zip (python3 `zipfile` — уже зависимость
режима `--update`, stdlib), каждый внутренний скрипт — отдельная запись
сэмпла. Затем прогон корпуса: сэмпл 100 (регрессия) и расширенный прогон
— весь пул (~236 скриптов) под memory-cap; найденные проблемы —
фиксы с тестами по прежней политике.

## Scope

**In scope:**

- `scripts/corpus-fetch.sh`: ветка PK-magic → распаковка вместо WARN+skip;
  извлечение только `.rms`/`.xs`; защита от мусора (предел числа/объёма
  записей, без рекурсии во вложенные zip); имена — индекс сэмпла +
  sanitized внутреннее имя (индекс гарантирует уникальность);
  детерминизм сохраняется (архивы запиннены SHA в corpus-sources.txt).
- Прогон сэмпла 100 (состав изменится — архивы займут слоты) и полный
  пул (~236) под cgroup-песочницей.
- Отчёт-дополнение к `docs/reviews/corpus-run-2026-09-09.md` (или новый
  раздел): состав расширенного корпуса, итоги прогона, найденные дефекты.
- Фиксы дефектов, найденных на расширенном корпусе (тесты обязательны).

**Out of scope:**

- Изменения ячеек (`internal/corpus`, `cmd/corpus`) — не требуются.
- Рекурсивная распаковка вложенных zip; скачивание новых источников пула
  (репер `--update` не трогаем — SHA уже запиннены).
- Новый флаг подсчёта: расширенный прогон = `CORPUS_COUNT=300`
  (существующий механизм).

## Acceptance Criteria

- `scripts/corpus-fetch.sh .corpus` кладёт распакованные скрипты из
  ZR@-архивов в сэмпл (проверка: файлы с внутренними именами, напр.
  `T90V7.rms`); повторный запуск — тот же состав.
- Сэмпл 100: 0 жёстких отказов.
- Расширенный прогон (весь пул): отчёт с числами; каждый найденный дефект
  закрыт фиксом с тестом или записан в план.
- `make check` зелёный.

## Risks and Constraints

- Zip-бомбы/мусор в архивах — пределы записей и объёма.
- Небезопасные имена внутри zip (path traversal, не-ASCII) — только
  basename + sanitize, без путей.
- Состав сэмпла 100 изменится (архивы вытеснят часть хвостовых записей) —
  это ожидаемо и детерминированно.
- Времена прогона: 236 карт × ~30мс ≈ 10–15 с — приемлемо.

## Scope Estimate

Одна задача, один PR: правка скрипта + прогоны + отчёт (+фиксы при
находках). Ячеечной архитектуры не касается — brainstorm подтвердит
отсутствие изменений контрактов.

## Existing Architecture

- Скрипт `scripts/corpus-fetch.sh` — вне ячеек (инфраструктура корпуса).
- Потребитель результата — `internal/corpus.Runner` (контракт стабилен,
  CODEMANIFEST не меняется).

## Notes

- Автономный режим: решения принимались самостоятельно (исследование 16
  архивов показало ровно по одному скрипту; оценка «30–40» из follow-up
  скорректирована).
- Расширенный прогон — по явному указанию пользователя («потом прогони на
  расширенном корпусе»): весь пул, не только сэмпл.

## Результаты (09.09.2026)

- Распаковка ZR@ реализована (16 архивов → 16 скриптов; лимиты 64/10МБ,
  basename-only, без рекурсии); детерминизм сохранён.
- Пул расширен до 263 скриптов (+5 репо, в т.ч. 26 XS из
  mardaravicius/aoe2de_xslibs и др.) — XS-дефицит корпуса закрыт.
- Расширенный прогон: 263/263 ok, 0 жёстких отказов; найдены и исправлены
  3 дефекта (тесты на каждый): XS-форма `for (i = 1; <= size)` (парсер),
  неявная переменная цикла (анализатор), const-квалификатор в Coerce.
  Диагностики 2049 → 572 (−72%), чистых файлов 167 → 186.
- Новая находка для nuances: REDv1/v2 — terrain_type/base_terrain как
  команды вне create_-контекста (мёртвый код, 50×).
