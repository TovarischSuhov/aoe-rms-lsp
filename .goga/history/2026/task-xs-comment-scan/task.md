## Description

Сделать скан комментариев регион-осведомлённым, не меняя контракт
`Comments` и поверхность диагностики:

- скан отслеживает inline-XS-регионы теми же предикатами, что и `run`:
  строка-директива `#includeXS` (по гашёной строке, как её видит `run`)
  открывает регион со следующей строки; регион закрывается на строке,
  которая для `run` — секционный заголовок или директива
- тело региона сканируется как независимая единица: состояние
  блок-комментария не пересекает границу региона ни в одну сторону;
  незакрытый `/*` внутри региона даёт экстент, обрезанный по конец
  региона («содержащийся» экстент), скан после границы продолжается с
  чистым состоянием
- терминатор региона, поглощённый открытым внутри региона блоком,
  распознаётся по сырой строке: экстент обрезается по конец предыдущей
  строки, терминатор остаётся видимым для `run` → `endXsBlock`
  срабатывает, секции после региона попадают в AST
- новых диагностик не вводим: acceptance #93 допускает «diagnostics or
  contained extent»; содержащийся экстент согласован с поведением
  незакрытого `/*` в EOF; незакрытый `/*` внутри XS-кода — забота
  xs-парсера содержимого блока
- поведение вне регионов не меняется

## Risks and Constraints

- модель регионов в скане обязана совпадать с обходом `run` (оба читают
  одну классификацию строк) — расхождение сразу ломает `endXsBlock`;
  страховка — тесты на терминатор секцией и директивой
- контракт `Comments`: экстенты внутри региона остаются в списке —
  пин-тесты comments_test.go без правок ожиданий
- CODEMANIFEST rms не описывает пересечение состояния комментария с
  границей региона отдельно — код приводится к уже задекларированному
  поведению (Algorithm: регион до следующей директивы/секции/EOF);
  уточняющая строка не требуется, при обнаружении расхождения — только
  через goga-change flow
- кромка: `/* c */ <X>` как первая строка тела — классификация сырой
  строки (не терминатор) против гашёной (терминатор): расхождение
  зафиксировано как out of scope, тест не добавляем (не-цель)
