# Architecture Plan: xs-comment-scan

## Topic

**xs-comment-scan** — регион-осведомлённый скан комментариев в ячейке rms
(P0-баг #93, size S-M; компактный arch → apply → TDD).

## Implementation Order

Только `internal/rms/parse.go` (функция `blankComments` + локальное
состояние скана). `run`, `endXsBlock`, `mergeComments`, `recordHashComment`
не меняются: после фикса они видят корректный `visible` и те же экстенты.
`internal/format` не меняется — защищён инвариант-сьютом. CODEMANIFEST не
меняется: код приводится к задекларированному поведению (регион до
следующей директивы/секции/EOF; контракт `Comments` сохранён).

## Дизайн-решения

- **Модель регионов живёт внутри `blankComments`** и зеркалирует обход
  `run` на тех же предикатах (`isDirectiveLine`, `xsTerminator`,
  `sectionHeader`; слово точное: `#includeXS`, без аргументной
  дифференциации — аргументed/бare для скана неразличимы, это рутина
  `run`/`endXsBlock`).
- **Классификация — на том же виде строки, что увидит `run`**: проверка
  границы после обработки строки идёт по гашёной строке (`TrimSpace`),
  так скан и обход гарантированно согласованы (`*/ #includeXS` — регион
  открывается; `/* c */ <X>` в теле — терминатор).
- **Единственное место сырой классификации** — терминатор, поглощённый
  открытым внутри региона блоком: до обработки строки проверяется
  `xsTerminatorPrefix(raw)` — префикс до первого маркера комментария
  (`/*`/`//`), чтобы комментарий-хвост на строке-терминаторе
  (`<X> /* keep`) не маскировал её; при срабатывании открытый экстент
  обрезается по конец предыдущей строки («содержащийся»), состояние
  сбрасывается, строка обрабатывается с чистого состояния → терминатор
  остаётся видимым для `run`, `endXsBlock` срабатывает.
- **Состояние блок-комментария не утекает из региона наружу**: блок,
  открытый в теле, обрезается на границе (выше). Вход в регион
  (директива `#includeXS` по гашёной строке) обрезает блок, открытый на
  самой директивной строке, по конец этой строки — экстент на
  директивной строке потребитель всё равно фильтрует
  (`dirLine`/`rawTo`). Блок, открытый ДО директивной строки, гасит саму
  директиву — регион не открывается вовсе (и скан, и обход видят одно
  гашёное; совпадает с запиненным поведением незакрытого `/*` вне
  региона). Блок, открытый НА строке-терминаторе после терминаторного
  текста, — RMS-сторона, продолжается обычным порядком.
- **EOF внутри региона**: существующий финальный фиксап (экстент до конца
  последней строки) уже даёт правильный содержащийся экстент — регион
  кончается в EOF тем же кодом, без ветвления.
- **Диагностик нет** (решение propose-стадии); `hashes`/`recordHashComment`
  не затронуты: `#`-строки тела по-прежнему не доходят до `recordHashComment`
  (их съедает `run`-обход), а отсканированные `/* */`/`//` тела по-прежнему
  попадают в `Comments`.

## Artifacts

### Cell: `internal/rms` — modify (без правок контракта)

**CODEMANIFEST**: без изменений — поведение уже покрыто декларациями
`Parse` (Algorithm: регионы `#includeXS` до следующей директивы/секции/
EOF) и `RmsFile.Comments`. При обнаружении расхождения на ревью — только
через goga-change flow.

**Код**: `blankComments` — добавление регионального состояния и двух
точек проверки (сырой пре-чек при открытом блоке; гашёный пост-чек),
обрезка экстентов на границах; инварианты функции сохраняются: длины
строк и смещения, гашение не трогает строковые литералы, `out[i]`
записывается для каждой строки.

**Тесты** (`internal/rms`, table-driven, same package, `t.Parallel()`):

1. репро #93: незакрытый `/*` в теле → секция и стейтмент после региона
   в AST, один `XsBlock`, `diags` пуст, экстент обрезан по конец региона
2. терминатор, поглощённый блоком: расширенное репро (после региона ещё
   секция+стейтмент) → оба в AST, `endXsBlock` отработал
3. закрытый `/* */` и `//` в теле → экстенты в `Comments` (пин-регрессия
   контракта; `TestRmsComments_HashInsideXsBlock` без правок ожиданий)
4. незакрытый `/*` в EOF вне региона → прежний экстент до конца файла
   (вне-региональное поведение не изменилось)
